# ESP32C3-chatbot

一块 ESP32-C3（4 MB Flash）上的 QQ 聊天机器人，自带网页管理后台。对话、记忆和配置全部跑在板子上，不需要额外的服务器。

## 功能

**聊天**

- 接入 QQ 开放平台，群聊 @ 和单聊都能用
- 同一份固件也编译了飞书、Telegram、微信通道，填好凭证重启即可启用
- 网页后台里可以直接和板子对话，按会话分文件保存（默认 `web`），与 QQ 的历史互不干扰
- 对话页左侧是聊天记录侧边栏，能新建、切换、删除会话，历史都存在板子上
- 接入 Tavily 或 Brave 搜索，模型遇到需要最新信息的问题会自己联网查

**记忆**

- 会话历史持久化在设备上，重启可以续聊
- 长期记忆按条目存储，网页上每行一条，可增删改
- 开启「自动记录」后，模型会把对话中的持久事实（称呼、在做的项目、手上的设备、稳定偏好）用中文自己写成条目，来源标记为 `auto`，相同内容由设备去重
- 自动记录复用工具调用链路，不需要额外的模型请求；关闭开关后模型不再拿到写记忆的工具
- 自动记录设有护栏：密钥/密码/令牌等凭证会被拒绝写入，换个措辞复述同一事实会去重，自动条目上限 24 条；网页手动编辑不受去重和上限约束
- 上下文接近模型窗口时按 token 阈值触发压缩，较早的内容生成摘要后保留

**人格**

- 人格写在 `/memory/soul.md`，网页里直接编辑，保存后下一次对话就生效
- 每次请求由记忆模块重新读取人格与档案文件，不需要重启

## 联网搜索

在「对话模型 → 联网搜索」里填 Tavily 或 Brave 的 API Key，保存后重启即可。两家都填时优先用 Tavily。模型会在需要最新信息时自己调用 `web_search`，最多取 3 条结果并把摘要带入上下文。

依赖两点：**模型接口要支持 function calling**（同一页的「工具调用」开关，默认开启），以及至少配置一个搜索密钥。没配密钥时这个工具不会注册，也不会占用模型上下文。

C3 没有 PSRAM，工具调用的那一轮请求会比普通对话多占内存。若偶发 `Out of memory`，缩短人格文件或换一个上下文窗口更小的模型即可。

## 网络诊断

「设备状态」页新增**链路质量**卡片和**开始网络自检**按钮，用来区分「Wi-Fi 弱」和「接口/服务端问题」：

- **信号强度**：实时 RSSI。−60 dBm 以上良好，−70 以下开始丢包，−80 以下容易出现握手超时
- **信道 / 开机后断连次数 / 上次断连原因**：原因码会翻成中文，如「认证过期」「信标丢失」
- **网络自检**：向模型接口连三轮，分别测 DNS 解析、TCP 建连和完整 HTTPS 往返，返回每轮耗时、HTTP 状态码和可用内存

判读方式很直接：

| 现象 | 结论 |
|---|---|
| DNS 或 TCP 就失败 | Wi-Fi 或路由器问题 |
| TCP 十几毫秒、HTTPS 近 1 秒、三轮全通 | 链路正常，慢在 TLS 握手（C3 算力限制） |
| 三轮返回 429 | 模型服务限流，与网络无关 |
| 网页整体打不开、ping 正常 | 模型请求把堆吃光，等它超时或重启设备 |

`GET /api/netdiag` 返回原始 JSON，方便脚本采集。自检本身要占用约 20 KB 堆，低于 45 KB 空闲时会直接返回 503，不会硬跑。

**网页后台**

七个分区：设备状态、对话、人格设定、长期记忆、对话模型、聊天通道、网络设置。纯手写 HTML 加原生 JS，没有构建步骤，直接打进固件。

## 已知问题

**带工具调用的轮次在 C3 上仍可能失败**：`web_search` 的第二次 LLM 请求会在 TLS 握手阶段报 `ESP_ERR_HTTP_CONNECT`，根因是峰值内存不足（无 PSRAM），不是网络。普通对话不受影响。完整的现象、实测数据、已排除方向和复现步骤见 [ISSUE-C3-TOOLCALL-OOM.md](./ISSUE-C3-TOOLCALL-OOM.md)。

## 硬件

- ESP32-C3，4 MB Flash
- 板型配置 `esp32_C3_4MB`
- 分区布局：factory 2816 KB / system 384 KB / storage 768 KB

当前固件约 1.5 MB，占 factory 分区的 52%，剩余约 1.3 MB。

需要注意的约束是 RAM 而不是 Flash：C3 没有 PSRAM，启动时可用堆约 262 KB，Wi-Fi 与 TLS 之后实际可用的通常在 60–100 KB。增加常驻内存的功能前先确认余量。

## 编译

需要 ESP-IDF v5.5.x。

```bash
. $IDF_PATH/export.sh
cd application/edge_agent
idf.py bmgr -c ./boards -b esp32_C3_4MB
idf.py build
idf.py -p COM6 flash
```

首次烧录后设备会开一个配网热点 `esp-claw-XXXXXX`。连上热点，浏览器打开 <http://192.168.4.1>，填写 Wi-Fi、模型接口和 QQ 机器人参数，保存后重启。

环境细节、分区布局和踩过的坑见 [BUILD_NOTES.md](./BUILD_NOTES.md)。

## 升级

改完代码只更新应用分区：

```bash
idf.py -p COM6 app-flash
```

人格、长期记忆和 Wi-Fi 凭证都会保留。

`idf.py flash` 会连同 storage 分区一起覆盖，人格和记忆会被重置。只在首次烧录或修改分区表时使用。
