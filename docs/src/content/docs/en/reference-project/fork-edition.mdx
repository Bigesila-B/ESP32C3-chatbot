## Differences from official ESP-Claw

This fork ships on `feature/context-compaction` and is based on upstream [`a4edfe5`](https://github.com/espressif/esp-claw/commit/a4edfe594a99407c8b4d5d70b93906bdd762b745). Upstream already provides Skills, Lua, a QQ bot integration, MCP, and model vision. The table describes the changes in this fork.

| Feature | Upstream baseline | Fork edition |
| --- | --- | --- |
| Chat help | Individual commands provide their own help | The Commands page and `/help` in chat show active commands, Chinese descriptions, the date, CPU and memory use, today's and this month's token counts, and the LAN address. |
| Reply notice | The default route sends “🦞 ESP-Claw is snapping on it...” | The rules used on a fresh setup omit the notice. Tool progress is still controlled by the device setting. |
| MCP | MCP Client and Server capabilities are available | The MCP Settings page can save one default server URL, test the connection, and use that URL for calls from chat. |
| Skills | Skills and Lua scripts are available | Optional MicroPython runs small Python scripts on ESP32-S3 boards with PSRAM. |
| Web images | The upload endpoint accepts up to 512 KiB per file | Web Chat and Files compress larger images in the browser. They prioritize dimensions and detail while keeping the uploaded file within the endpoint limit. |
| Session memory | Compaction starts at a session file size threshold | A context window setting adds a model-dependent compaction threshold. Compaction prioritizes recent turns and tries to summarize older content. |
| Full storage | A failed session index rebuild can interrupt a reply | If history is unreadable and the index cannot be rebuilt, the device attempts the current reply. Uploads report low storage, and a Skill activation interrupted by full storage can recover after space is freed. |

As of November 14, 2026, upstream `master` is [`50072775`](https://github.com/espressif/esp-claw/commit/50072775cfa20d7ce25a9b27591d9d7c8b9dbab5) and includes persistent web chat history. This fork uses an earlier baseline. Refreshing Web Chat clears the messages on the page, while the device stores the model's session memory separately.

## Usage

- **Commands and usage.** Open Commands in the browser or send `/help` in chat. Web Chat uses the device icon in the help header. The device handles help locally, with zero model tokens. Usage comes from the model API and is counted from activation onward in the device's time zone. Use the displayed IP address to open the settings page on the LAN.
- **Remove the fixed notice on an existing device.** An upgrade keeps existing routes. If the lobster notice still appears, run `auto rules` in the device's serial console, confirm the rule exists, and run `auto delete_rule im_any_message_working_reply`.
- **Connect to MCP.** In System Settings → MCP Settings, enter an HTTP(S) server URL reachable from the ESP32, test the connection, and save it. Enable MCP Client for the LLM in Capabilities and restart the device to use MCP tools in chat. The service needs a Streamable HTTP endpoint.
- **Install a Python Skill.** When building, enable `App Claw Config → App Claw Capabilities → Enable MicroPython scripts for Skills` in `idf.py menuconfig`. Declare the `cap_micropython` tool group in the Skill's `SKILL.md`, then call `python_run_script` on `{CUR_SKILL_DIR}/scripts/...`, with JSON input in `args` and results via `print()`.
- **Send a large image.** Select the image in Web Chat and send it when the upload is ready. Files of 512 KiB or smaller are uploaded as-is. For larger images, the browser attempts to preserve dimensions before lowering JPEG quality or resizing as necessary. A PNG converted to JPEG gets a white background, and a compressed animation keeps one frame. Use a vision model that accepts device-uploaded images.
- **Set the context window.** Enter the model's window in System Settings → LLM Settings, or use 0 or an empty value to match by model name. The device starts compaction at about 60% of that window, with a fallback threshold of about 150 KiB of session data. Use `/session new` to start a session and `/session list` to see existing ones.

## ESP32-S3 test coverage

Chat help, token counts, MCP tool calls, a custom Python Skill, large Web image uploads, and replies with full storage were tested on an ESP32-S3 with 16 MiB Flash and 8 MiB PSRAM. The test application with MicroPython enabled is 3,001,840 bytes, leaving about 869 KiB in that board's 3,800 KiB app partition. Check the build output and partition table for your board.

MicroPython is an optional embedded runtime. The test configuration allocates a 256 KiB PSRAM heap, and the runtime supports selected built-in modules and imports from the script directory. A script file can be up to 32 KiB, with a 1-second default timeout, a 5-second maximum, and up to 4,095 bytes of captured output. Skills that rely on desktop Python packages or system commands need adaptation. Use the existing Lua modules and capabilities for device and network I/O.

With full storage, saving new messages to history may fail. If QQ returns `ESP_FAIL`, check available space in Files. The test covered the session failure caused by full storage, with QQ delivery handled separately. Long-session summary behavior still needs validation.
